# NGD Boilerplate Drupal Pantheon Upstream

This is a custom [Pantheon](https://pantheon.io) upstream for Drupal 11, built on top of Pantheon's [Drupal Composer Managed](https://github.com/pantheon-upstreams/drupal-composer-managed) upstream. It uses Pantheon's [Integrated Composer](https://docs.pantheon.io/guides/integrated-composer) build process to manage dependencies.

Unlike earlier Pantheon upstreams, files such as Drupal Core that you are unlikely to adjust while building sites are not in the main branch of the repository. Instead, they are referenced as dependencies that are installed by Composer.

## Repository Structure

```
├── .gitignore
├── composer.json              # Site-level composer configuration (do NOT modify for upstream changes)
├── pantheon.upstream.yml      # Pantheon platform configuration (build_step: true enables IC)
├── README.md
├── CHANGELOG.md
├── config/                    # Drupal configuration export directory
├── recipes/                   # Drupal recipes directory
├── upstream-configuration/
│   ├── composer.json          # Upstream-level dependencies (shared across all downstream sites)
│   ├── README.md
│   └── scripts/
│       └── ComposerScripts.php
└── web/
    └── sites/
        └── default/
            └── settings.php
```

### Key Files

- **`.gitignore`** — Prevents [build artifacts](https://docs.pantheon.io/guides/integrated-composer#build-and-deploy-terminology) generated by Composer from being committed to the upstream or site code repositories. Changing the tracking status of Composer-managed files and directories can result in build failures or unexpected errors.

- **`composer.json`** (root) — Site-level customizations. Individual sites created from this upstream can modify this file. **Do not modify this file for upstream-wide changes** after the upstream has been published.

- **`upstream-configuration/composer.json`** — Upstream-level dependencies shared across all downstream sites. Add upstream dependencies here using the `composer upstream-require` command.

- **`pantheon.upstream.yml`** — Platform configuration. The `build_step: true` directive enables Pantheon's Integrated Composer build process. Also configures PHP version, database version, HTTPS enforcement, and protected web paths.

## Important: `composer.lock`

**Do NOT commit `composer.lock` to this upstream repository.**

When a site is created from this upstream, Pantheon runs `composer install`, generates a `composer.lock` file, and commits it back to the site's code repository. Committing `composer.lock` from the upstream would cause merge conflicts when downstream sites apply upstream updates.

The `composer.lock` file should **not** be listed in `.gitignore` because it must be committed for individual downstream sites. To avoid accidentally committing it when working directly with this upstream, run:

```bash
echo /composer.lock >> .git/info/exclude
```

> **Note:** The `exclude` file is local to your clone and is not pushed to the remote. You must re-run this command every time you make a new local clone of the upstream.

## Adding Dependencies to the Upstream

1. Clone this repository.

2. Require the upstream management package if you have not already:

   ```bash
   composer require pantheon-systems/upstream-management:^1
   ```

3. Use the `composer upstream-require` command for each dependency:

   ```bash
   composer upstream-require drupal/pkg-name [--no-update]
   ```

4. Commit and push your changes. **Remember to _not_ commit the `composer.lock` file.**

## Updating Dependencies in the Upstream

To pin specific dependency versions across all downstream sites without causing merge conflicts:

1. Run `composer update-upstream-dependencies` in this repository. This will:
   - Create or update `upstream-configuration/composer.lock`
   - Create or update `upstream-configuration/locked/composer.json` with pinned versions
   - Update the root `composer.json` repositories section to use `upstream-configuration/locked`

2. Commit the changes and push.

## Maintaining the Upstream

- **Increment the version** in `upstream-configuration/composer.json` each time you make edits. Composer checks the root `composer.json` for changes that should be pushed to the upstream configuration.

- **Verify changes** by running `composer install` or `composer update` in the `upstream-configuration` directory. Be careful not to rely on ["root-only" properties of composer.json](https://getcomposer.org/doc/04-schema.md).

- **Build artifacts** are stored in Git tags like `pantheon_build_artifacts_$BRANCHNAME`. All build artifacts must be ignored in `.gitignore`. Add entries any time you modify the build to move installation files to new locations.

## Applying Upstream Updates from Pantheon

This upstream tracks Pantheon's official Drupal Composer Managed upstream. To pull in updates:

```bash
git fetch pantheon-updates
git merge pantheon-updates/main
```
